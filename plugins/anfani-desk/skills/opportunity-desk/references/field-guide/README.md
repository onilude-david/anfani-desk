# Field guide: how to fill any application

Researched October 2026. Deadlines, rules and policies change: check each programme's own page before acting.

How programmes read, score and reject, and what their forms ask, built from several hundred pages opened in full.
Each chapter lists its own sources, with pages seen only in search results marked separately. The guide decides the
shape of an answer; every fact in an answer comes from the applicant's profile file `desk/profile.md`. Nothing in
the guide is pasted into an answer.

**Where the examples come from.** The scoring patterns are global. The programme lists lean towards Africa, with
many Nigerian and Lagos examples, and the YC chapter's company and visa steps were written for Nigerian founders.
For other countries, use the method, then check local rules (registration, tax, visas) on official pages for the
user's own country; never apply another country's rule.

## How the desk uses it

1. **Classify the form.** Tag every field with its type number from `question-bank.md`, then read the chapter for
   the category.
2. **Read the programme's own words.** Copy its criteria into the answer sheet. A profile row is a lead, not a
   fact: check every deadline, limit and rule on the programme's own page that day.
3. **Answer by structure, from the record.** The structure comes from the guide; every fact comes from
   `desk/profile.md`, with `[TBC]` for anything only the applicant knows.
4. **Respect the AI policy.** Rules differ per programme. Where a programme forbids AI-written answers, the desk
   prepares the record and the checklist only; the applicant writes.
5. **Keep it current.** When a profile row proves wrong (a date, a rule, a closed programme), fix the row and date
   the fix. Re-research any chapter older than six months.
